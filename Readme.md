# TaskMGR

Локальное Android-приложение для управления задачами, покупками, справочником, заметками, подписками, ЖКХ и личными финансами. Всё хранится на устройстве в SQLite, без сети и аккаунтов.

## Возможности

- **Разделы и вкладки** — задачи группируются по разделам (Дом, Гараж, Авто, IT, Здоровье, Развлечения, Работа, Животные, Спорт, Учёба, Private) и вкладкам внутри них
- **Задачи** — название, описание, приоритет (важно / обычно / потом), срок (точная дата, период, по пробегу, без срока), повтор
- **Повторы** — без повтора, по пробегу, по месяцам, по пробегу или месяцам; при выполнении автоматически создаётся следующая задача
- **Покупки** — название, цена, категория, отметка «куплено», сумма не купленного по категории и по вкладке
- **Справочник** — пары «название — значение» с категориями и описанием
- **Заметки** — быстрые заметки с датой создания и редактирования
- **Подписки** — название, сумма, день списания, дата следующего списания, описание, активность; сводка «в месяц / в год», отметка «оплачено» со сдвигом на месяц
- **ЖКХ** — квитанции по месяцам и домам, счётчики (название, единица, тариф), показания с расчётом расхода и суммы, статистика по счётчикам и месяцам
- **Финансы** — периоды (по датам поступлений), поступления (зарплата/аванс и т.п.), шаблоны трат, траты и запланированные траты (из шаблонов, подписок, покупок), сводка «Доход / Запланировано / Факт / Свободно», темп и «можно тратить в день», статистика по категориям и периодам; перевод записей «факт ↔ план»
- **Отказ от курения** — журнал выкуренных сигарет, счётчик «дней без сигарет», статистика «сегодня / всего / в среднем в день» и факты-достижения (10+ и 20+ сигарет в день, 1/3/7/14/30/90/365 дней без сигарет)
- **Главный экран** — настраиваемые плитки разделов и инструментов, ленты «Дедлайн» (просроченные, горящие и скоро) и «Важные» (приоритет «важно»), бейджи активных задач на плитках разделов
- **Статистика** — сводка (Всего / Активных / Выполнено / Просрочено), по приоритетам, по разделам (с просрочкой), выполнено за период, медианное время от создания до выполнения, выполнено в срок, покупки
- **Приватный раздел** — скрыт за PIN, разблокируется на сессию, при блокировке его вкладки исключаются из главного экрана, статистики и импорта покупок в финансах
- **Уведомления** — утренняя и вечерняя сводки (задачи + подписки), настраиваемое время, каналы уведомлений, перепланирование после перезагрузки
- **Проверка обновлений** — кнопка в настройках уведомлений: проверка последнего релиза на GitHub, скачивание APK и запуск системного установщика
- **Локальное хранение** — SQLite на устройстве, без интернета и внешних сервисов (кроме проверки обновлений)

## Технологический стек

- **Основной язык** — Java 17
- **Платформа** — Android (minSdk 24, targetSdk 34)
- **База данных** — SQLite через `SQLiteOpenHelper` (версия схемы 14)
- **UI** — Material 3, RecyclerView, View-адаптеры, кастомная тёмная тема «Neon Garden»
- **Сборка** — Gradle (Groovy DSL), Android Gradle Plugin
- **Хранение секретов** — PBKDF2 (HMAC-SHA256 / SHA1 в зависимости от API) для PIN приватного раздела
- **Асинхронность** — собственный `DbExecutor` (один фоновый поток для SQLite + `Handler` на main)
- **Уведомления** — `AlarmManager` + `BroadcastReceiver`, каналы `NotificationChannel`
- **Обновления** — GitHub Releases API, `FileProvider` для установки APK

## Архитектура

Проект разделён на слои по пакетам:

- **data** — `DatabaseHelper` (синглтон), `MainPlatesCatalog` (каталог плиток) и DAO (`data/dao/*`)
- **model** — модели данных (`Task`, `Tab`, `Section`, `ShoppingItem`, `ReferenceEntry`, `HistoryEntry`, `Subscription`, `UtilityMeter`, `UtilityPeriod`, `UtilityReading`, `FinanceIncome`, `FinancePeriod`, `FinanceExpense`, `FinanceTemplate`, `QuickNote`, `MainPlate`, `SmokingEntry`)
- **service** — бизнес-логика (`TaskService`, `UrgencyCalculator`, `TaskUrgencyComparator`, `NotificationScheduler`, `DigestBuilder`, `UpdateChecker`, `SmokingStats`, `SmokingFacts`)
- **receiver** — `TaskReminderReceiver` (сводки), `BootReceiver` (перепланирование будильников)
- **ui** — экраны и адаптеры:
    - `ui/main` — главный экран, настройка плиток
    - `ui/section` — раздел и его вкладки
    - `ui/tab` — вкладка (задачи, покупки, справочник, история)
    - `ui/stats` — общая статистика
    - `ui/notes` — заметки и редактор
    - `ui/subs` — подписки
    - `ui/utilities` — ЖКХ (квитанция, статистика)
    - `ui/finance` — финансы (периоды, настройки, статистика)
    - `ui/smoking` — отказ от курения (счётчики, факты, история)
    - `ui/common` — общие диалоги (выполнение задачи, настройки уведомлений)
- **util** — общие утилиты (`DbExecutor`, `PasswordHasher`, `AppLock`, `PinInputHelper`, `DateUtils`)

## Быстрый старт

### Предварительные требования
- JDK 17
- Android SDK (compileSdk 34)
- Android Studio или Gradle CLI

### Локальный запуск

**1. Клонировать репозиторий**

```shell
git clone https://github.com/<username>/TaskMGR
cd TaskMGR
```

**2. Собрать debug-сборку**

```shell
./gradlew assembleDebug
```

**3. Установить на устройство/эмулятор**

```shell
./gradlew installDebug
```

Или открыть проект в Android Studio и запустить через Run.

## Особенности реализации

### Структура данных

- **Section** — раздел (Дом, Гараж, Авто, IT, Здоровье, Развлечения, Работа, Животные, Спорт, Учёба, Private)
- **Tab** — вкладка внутри раздела; для раздела «Авто» хранит год и текущий пробег; флаги `show_tasks`, `show_shopping`, `show_reference`
- **Task** — задача вкладки: приоритет, статус, тип срока (дата / период / по км / нет), поля срока, правило повтора
- **HistoryEntry** — факт выполнения задачи: время, пробег на момент выполнения, заметка
- **ShoppingItem** — покупка вкладки: цена, категория, флаг «куплено», флаг «выбрано»
- **ReferenceEntry** — запись справочника: название, значение, категория, описание
- **QuickNote** — заметка: тело, дата создания, дата обновления
- **Subscription** — подписка: название, сумма, день списания, дата следующего списания, описание, активность
- **UtilityMeter** — счётчик: название, единица, тариф, активность
- **UtilityPeriod** — квитанция: год, месяц, дом, заметка, оплачено/дата оплаты
- **UtilityReading** — показание: счётчик, предыдущее/текущее значение, расход, применённый тариф, сумма
- **FinanceIncome** — поступление: название, сумма, день месяца, активность
- **FinancePeriod** — период: начало, конец, название, суммарный доход, заметка
- **FinanceExpense** — трата: период, категория, описание, сумма, тип источника (`manual`, `template`, `subscription_bundle`, `shopping_bundle`), ссылки на источники
- **FinanceTemplate** — шаблон траты: категория, описание, сумма по умолчанию, активность
- **MainPlate** — плитка главного экрана: ключ, подпись, иконка, тип (раздел / приват / активити), видимость, порядок
- **SmokingEntry** — запись журнала курения: время, количество сигарет, заметка

### Приватный раздел

- PIN хранится как PBKDF2-хеш (соль + итерации + хеш в `app_settings`), сам PIN не сохраняется
- Разблокировка действует на сессию (`AppLock`), сбрасывается при убийстве процесса
- При заблокированном приватном разделе его вкладки исключаются из главного экрана, статистики и импорта покупок в финансах

### Выполнение задач и повторы

- Выполнение задачи пишет запись в историю, помечает задачу `done`, обновляет пробег вкладки (если передан) и при повторе создаёт следующую задачу
- Пробег вкладки не уменьшается: пишется только если новое значение больше текущего
- Поддерживаемые повторы: `by_km`, `by_months`, `by_km_or_months`; для `by_km_or_months` следующая задача получает и дату, и пробег, а срочность считается по худшей из оценок

### Целостность данных

- Выполнение задачи выполняется в одной SQLite-транзакции: история, статус, пробег и следующая задача — либо всё, либо ничего
- `DatabaseHelper` — синглтон на приложение (`applicationContext`), один экземпляр на процесс
- Внешние ключи включены (`onConfigure` → `setForeignKeyConstraintsEnabled(true)`), удаление вкладки каскадно удаляет её задачи, историю, покупки и справочник
- Записи финансов ссылаются на период по `period_id`; при удалении периода каскадно удаляются его траты

### Срочность

- `UrgencyCalculator` определяет срочность: `OVERDUE` / `SOON` / `NORMAL` / `NONE`
- Для дат: просрочено, если `due_date` раньше начала текущего дня (день дедлайна ещё не просрочен); «скоро» — в ближайшие 3 дня
- Для периода: просрочено, если `due_to` раньше начала текущего дня
- Для пробега: просрочено при остатке ≤ 0 км, «скоро» — ≤ 500 км
- `TaskUrgencyComparator` сортирует задачи: сначала `OVERDUE`, затем `SOON`, `NORMAL`, `NONE`; внутри группы — по расстоянию до дедлайна; задачи без срока — в конце

### Плитки главного экрана

- Каталог плиток (`MainPlatesCatalog`) — фиксированный набор: разделы (Дом, Гараж, Авто, IT, Здоровье, Развлечения, Работа, Животные, Спорт, Учёба), Private, заметки, ЖКХ, статистика, подписки, финансы, курение
- Видимость и порядок хранятся в `main_plates` (`plate_key`, `is_visible`, `sort_order`)
- На экране настройки плиток: свитч видимости и drag-handle для перетаскивания (через `ItemTouchHelper`); порядок сохраняется в БД одним `reorder` после отпускания
- Бейджи активных задач показываются на плитках разделов (кроме инструментов и Private)
- Плитки инструментов (Заметки, ЖКХ, Подписки, Финансы, Курение) и Статистика открывают соответствующие активити
- Лента «Дедлайн» включает просроченные задачи: точная дата без нижней границы по времени, диапазон и пробег — по тем же правилам срочности, что и в остальном приложении

### Уведомления и сводки

- Две сводки: утренняя (задачи на сегодня + ближайшие списания подписок) и вечерняя (задачи на завтра)
- Время настраивается в диалоге «Уведомления»; там же — вкл/выкл для каждой сводки
- Для подписок: вкл/выкл напоминаний и окно «за 1 / 3 / 7 дней»
- Планирование через `AlarmManager` (`setExactAndAllowWhileIdle`, с fallback на `setAndAllowWhileIdle` при отсутствии разрешения на точные будильники)
- После перезагрузки устройства будильники перепланируются (`BootReceiver`)
- Каналы: `digest_morning`, `digest_evening`

### Проверка обновлений

- Кнопка «Проверить обновления» в диалоге уведомлений
- Запрос к GitHub Releases API (`/releases/latest`), сравнение `tag_name` с `BuildConfig.VERSION_NAME`
- Черновики и пререлизы игнорируются; APK ищется по имени `taskmgr-*.apk`
- Скачивание APK во временную папку и запуск системного установщика через `FileProvider`

### Финансы

- Периоды генерируются автоматически на 6 месяцев вперёд по дням поступлений (например, 10 и 20 число — два периода в месяц)
- Каждый период имеет доход (сумма поступлений, попавших на его начало) и список трат
- Траты бывают двух видов:
    - **факт** (`source_type = manual`) — вносится вручную, идёт в «Потрачено»
    - **план** (`template`, `subscription_bundle`, `shopping_bundle`) — из шаблонов, подписок, покупок; идёт в «Запланировано»
- Импорт покупок: двухшаговый (вкладка → позиции), только некупленные или с пометкой «✓ куплено», категория — из `shoppingItem.category` (если есть) или имя вкладки; приватные вкладки не показываются
- Импорт подписок: за период, только те, что ещё не добавлены, одной bundle-записью с суммой и списком id
- Импорт шаблонов: чекбоксы, каждая трата отдельной записью
- Сводка периода: **Доход / Запланировано / Потрачено (факт) / Свободно**, плюс «Потрачено в день (факт)», «Осталось дней», «Можно тратить в день», «План ещё не выполнен»
- Долгий тап по плановой записи → «Отметить как потраченное» (меняет `source_type` на `manual`), «Редактировать», «Удалить»
- Обратный перевод: тап по факту → «Отметить как план» (меняет `source_type` на `planned`), а в диалоге редактирования тип «Факт/План» теперь сохраняется в БД
- Статистика: по категориям, по периодам, средний расход в месяц

### ЖКХ

- Дома: список домов/адресов, создание квитанции на месяц
- Счётчики: название, единица, тариф; можно добавлять и включать/выключать
- Показания: предыдущее/текущее значение, расход, применённый тариф, сумма; предыдущее значение подставляется из последнего текущего показания этого счётчика
- Квитанция: итог по месяцу, отметка «оплачено» с датой, заметка
- Статистика: по счётчикам и по месяцам (список «месяц + сумма + полоса»); период — 6 / 12 / 24 месяца; фильтр по дому

### Подписки

- Список с сортировкой: активные по дате следующего списания, затем неактивные по имени
- Стикер с датой: обычный / «скоро» (≤ 3 дня) / «просрочено» / «неактивна»
- Действия: «Оплачено (сдвинуть на месяц)», «Редактировать», «Удалить»
- Сводка «В месяц / В год» по активным подпискам

### Заметки

- Список заметок (сортировка по дате создания DESC), создание, редактирование, удаление
- Хранятся в `quick_notes` (тело, created_at, updated_at)

### Отказ от курения

- Журнал `smoking_log` (время, количество сигарет, заметка); быстрая кнопка «Выкурил сигарету» и диалог с датой/временем
- Счётчики: «дней без сигарет» (от последней записи), «сегодня», «всего», среднее в день за период наблюдений
- Факты (`SmokingFacts`) зависят от статистики: достижения за 1/3/7/14/30/90/365 дней без сигарет и факты о максимальном дневном количестве (10+, 20+)
- История последних записей; долгий тап — удалить запись, меню — очистить историю
- Плитка «Курение» добавляется миграцией БД и открывает `SmokingActivity`

### Статистика

- Строки разделов и приоритетов с нулевыми значениями не показываются; карточки «По разделам», «По приоритетам» и «Покупки» скрываются, если данных нет
- «Выполнено в день дедлайна или раньше» считается одинаково за всё время и за период: сравниваются календарные даты выполнения и дедлайна в локальной зоне

## Сборка

Проект использует Gradle wrapper. Если Gradle подхватывает не ту версию JDK, укажи её явно:

```properties
# gradle.properties (локально, не коммитить)
org.gradle.java.home=C:\\path\\to\\jdk-17
```

Или задай JAVA_HOME перед сборкой:

```shell
$env:JAVA_HOME="C:\path\to\jdk-17"
./gradlew clean assembleDebug
```

Сборка без ошибок: `./gradlew clean assembleDebug`.

Для release-сборки используются переменные окружения: `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
